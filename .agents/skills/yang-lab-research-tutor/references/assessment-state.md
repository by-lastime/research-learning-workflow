# 评估：判断证据，不把答题形式当理解本身

## 审阅实际提交

按实际题目版本读取用户原文；不要只看历史总结。旧答案按旧题接受，漏答新题不倒算旧题错误。只整理题目不顺便批改；修改教材/Skill不升级能力。原始答案与实验不覆写，批改另记。

分别记“已答对”“表述有歧义”“遗漏/未测到”“明确概念错误”。数字碰巧同shape不等于轴已解释；但漏写轴也不能直接认定不知道。原文多写一步、位置数写成索引列表等，先定位实际差异，不无依据推断整个流程都没掌握。

用户澄清时同时保留原句与澄清，调整教学优先级；自述不自动等同独立验收，新出现的实际正确输出也不能被旧错误永久压住。提示情况未知就写未知，不默认闭卷独立或依赖帮助。

## 最小反馈，按依赖推进

| 证据情况 | 行动 |
|---|---|
| 方法与变式均有正确输出 | 复用该能力，推进新主题，不重做同类整套题 |
| 用词不准、答案局部遗漏 | 给准确边界，必要时随下一讲短核对 |
| 误解会阻塞下一主题 | 只补最小依赖，用不同例子核验，再接回主线 |
| 概念与代码表现矛盾 | 对同一个动作作定点追踪，不能只挑最好或最差答案 |
| 教材漏讲、例子混乱 | 先修教学；未教内容不算用户失败 |
| 尚未学习或无证据 | 标未评估，不当作错误或掌握 |

先给“能否推进”的结论及理由，再列关键正确证据与剩余项。题量以信息缺口决定，不按固定题数填量。可直接解释纠正，也可适度提示；不强迫走提示阶梯或让用户多轮猜答案。

补讲必须有具体目标和退出条件。同一缺口重复出现时改变解释/测法，而不是生成措辞不同的同一长讲义。只有影响后续理解的缺口阻塞推进；可带到下一讲的残余项明确放在哪里核验，不能无限挂起。

## 练习与正式验收分开

练习由当前教材支持，优先图表解释、代码追踪、轴含义、反事实、结果判断和新条件迁移；不要求长矩阵、指数、三角函数或梯度手算。用户答案放独立文件，待做题不附整套标准答案。改讲义而题目未变时沿用作答文件。

允许进入下一讲 ≠ 当前每项全对 ≠ 整篇正式通过。整篇验收只使用项目`07_讲图与答辩验收标准.md`；它的覆盖要求不是每篇讲义都要再做一次的门槛。

## 状态维护

实质批改后，在现有对应评估中记录题号/关键原话、正确证据、差异、提示情况与下一步，再更新状态摘要和当前入口。不要在三个文件复制同一份长报告，不为一次反馈新建多份计划。未解决项须有后续处理位置；已解决旧项应被新结论替代。

分开E解释、M符号/数学、C代码、X实验、R比较/局限。看懂/解释代码不等于独立实现；教材发布和助手运行不是用户能力证据。

进度询问默认用“已确认／待核对／未学习或未评估”报告。用户明确要百分比时说明口径、依据和不确定性；没有量化规则就不要给看似精确的分数或承诺剩余工作量。规则整理不修改既有掌握证据。
