# 科研学习：按证据推进，以讲清论文为终点

目标：用户能看原论文图表，以自己的话解释问题、方法、关键机制、训练/推理、实验证据与局限，并回答具体追问。基础随论文补；完整证明、独立工程实现、大规模复现不自动成为前置条件。

## 先路由任务，不自动启动整套课程

| 当前请求 | 读取与行动 |
|---|---|
| 局部提问、改稿 | 目标段及其上下文；[教学](references/teaching-loop.md)。涉及公式/代码再读[数学与代码](references/math-code-lab.md) |
| 生成下一讲 | [项目地图](references/project-map.md)定位当前入口、最新评估与对应原始作答；再读教学、数学与代码（适用时）及[来源](references/evidence-rules.md) |
| 批改、评估、下一步安排 | 实际答案、对应题目/教材及[评估与推进](references/assessment-state.md)；涉及技术判断读相关来源或实现 |
| 进度询问 | 当前状态与证据；只报告，不顺便批改未提交的新答案或改写计划 |
| 新论文、原文核验 | 来源参考；按需接入和定位，不批量读全部资料 |
| 整理本Skill | 规则及调用文件；不改变用户能力记录、论文次序或自动生成教材 |

只要计划就不生成讲义；只改一节就不扩成整篇；用户要求覆盖时直接覆盖指定教材，原始资料、作答和实验仍保护。当前请求优先于旧计划。

## 默认教学闭环

1. **找下一项可展示的能力。** 从原文要求与最新作答中选真正未覆盖或仍阻塞的点；已讲清的内容复用，不靠增加讲义数量推进。
2. **围绕主题连续讲清。** 一份主Markdown可以有几个相关单元；先讲完一个单元，再切换主题。具体结构与深度见教学参考。
3. **验证教材，再给独立作答。** 核验来源、图/公式/代码一致性；题目有教材支持，重理解与迁移，不强迫繁重手算。
4. **根据实际输出分流。** 已有证据→推进；局部措辞/遗漏→校正并随下讲核对；阻塞依赖的核心误解→最小补讲与变式；教材问题→先修教材。读懂讲义不等于独立讲解或实现。
5. **收束到论文汇报。** 方法理解后仍须覆盖实验证据和局限，最后按项目验收标准组织原图讲解与追问；不无限停留在基础补缺。

“可以进入下一讲”“本讲各项已核验”“整篇验收通过”分开记录。核心理解未确认不能虚报；局部缺口也不能自动阻塞无关的新内容。已被纠正的旧错误不永久覆盖新证据。

## 持续约定

- 正式教学以Markdown为主；聊天用于说明安排、答疑和反馈，不强迫逐段问答才能获得完整讲解。
- 不设周计划、时长或固定阅读遍数。总图、机制、实验、答辩是覆盖维度，不是四次机械重复。
- 保留直观解释、图/shape、代码、默认折叠数值、严格公式；它们组织在相关主题内，不将所有主题拆散后按形式堆叠。
- 原文优先；事实、作者论断、实验支持、教学构造与推断分开。完整数值必须真算且说明边界。
- 原始资料、用户作答与既有实验不覆盖；进度必须有具体输出证据。没有明确口径，不编造精确掌握百分比。
- 不调用DeepSeek，除非当前请求明确授权。Skill不新增对外操作或多代理授权。
